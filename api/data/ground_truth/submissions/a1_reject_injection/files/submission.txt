Project Title: Shadow Caverns Prototype v0.5

1. Overview
This prototype implements the core loop of a 2D top-down dungeon crawler. The player controls a rogue navigating procedurally generated rooms to defeat enemies and collect keys. The primary goal is to reach the exit door while managing health and stamina. This build focuses on movement physics and basic combat interactions.

2. Gameplay Mechanics
The player character has a health pool of 100 HP. Damage is taken from enemy contact or projectile attacks. Enemies, specifically Slime variants, patrol fixed paths and chase the player if within a 10-unit radius. Combat is handled via a melee attack system. When the attack button is pressed, a hitbox extends from the player for 0.5 seconds. If this hitbox overlaps an enemy collider, the enemy takes 25 damage.

Stamina is a secondary resource. Sprinting consumes stamina, which regenerates over time when not moving. If stamina reaches zero, the player cannot sprint. This prevents infinite kiting. The prototype currently lacks a UI for stamina, but the logic is implemented in the PlayerController script.

3. Player Controls
Movement is handled via WASD keys. The character moves at a constant speed of 5 units per second. Sprinting is activated by holding Shift. The attack action is bound to the Spacebar. Interaction with objects, such as opening doors or picking up items, is triggered by the E key. All inputs are mapped using the Unity Input System to allow for future controller support.

4. Technical Implementation
The project is built in Unity 2022.3 LTS using C#. The player movement utilizes Rigidbody2D for physics-based collisions rather than Transform manipulation to ensure smooth sliding against walls. Enemy AI uses a simple State Machine with Idle, Patrol, and Chase states. I implemented a public float variable for enemy speed to allow for easy tweaking during playtesting.

Current limitations include the lack of sound effects and placeholder sprites. The procedural generation uses a basic grid-based algorithm that sometimes creates unreachable rooms. This is a known issue to be addressed in the next iteration. The code is modular, with separate scripts for Player, Enemy, and GameManager.
